# 0007 — Small exact labels and bounded ID-to-label pages

Task 013 follows merged task 012 (`b44520f`). Scope is small exact label requests and optional bounded metadata pages; large request spill and persistent lookup indexes remain tasks 014–015/M5.

`Reader::lookup_labels(&[&[u8]]) -> Result<LabelMatches>` owns copies of request bytes and ordered descriptors. `LabelMatches::{len,is_empty,get,statistics}` preserves zero-based request ordinal, exact bytes and optional original UelId. Duplicates produce separate ordered results; unknowns are None; if a stored table repeats identical bytes, choose the first file ID. Labels longer than the format's 255 bytes are InvalidOptions. Validate all sizes before allocation. The sum of byte storage, result descriptors and temporary sorted ordinal indices is capped at 128 KiB, also charged to the root quota; larger requests return BudgetTooSmall until the spill path exists. Fixed state reserves 16 KiB. In-place sorting of ordinal indices creates no hidden heap buffer. A nonempty batch performs one complete UEL traversal, including the closing marker; empty requests perform none. Counters report traversals/decoded entries, not performance claims.

`Reader::selection_from_labels(symbol, dimension, matches)` validates source identity and dimension, then selects the union of known IDs. Unknowns contribute no ID; empty/all-unknown requests create an explicit empty selection with no record I/O when scanned. The temporary ID buffer and the selection's owned ID copy are both quota-charged and released by ownership. No implicit string conversion, case folding or label renumbering occurs.

`Reader::uel_labels() -> Result<UelLabelCursor>` supplies lending `get(UelId) -> Result<&[u8]>`. Each cursor holds at most two pages of 128 fixed bounded byte strings, with implicit consecutive IDs and one complete metadata byte-cursor checkpoint after each page. Checkpoints are for string-table context only, not record restarts. On a miss, resume from the nearest retained predecessor checkpoint, or rescan from the table start. No ordinal directory grows with the file. Eviction is least-recently-used among two slots; evicted checkpoints are discarded. Random cold lookups may scan a prefix.

A source-wide secondary quota enforces `metadata_cache_bytes` across all cursors, while root reservations still charge actual memory. Each cached page charges 128 × size_of::<Bytes>() plus the complete page/control/checkpoint header to both allowances (root header storage is conservatively included in cursor state). No encoded/compressed block survives page fill; temporary Stream/codec scratch is separately root-charged and dropped before returning a label. Zero/tiny cache allowances or unavailable optional page quota use uncached bounded scans; no capacity is silently raised. Allocation failures and required decoder quota failures propagate. `Reader::metadata_cache_statistics()` reports current/peak/limit cache charges; per-cursor counters distinguish hits, misses, evictions, entries decoded and table/checkpoint restarts.

All returned labels borrow their cursor until the next get; independent cursors have no shared decoder lock. Check source immutability even on cache hits. Read/reference/allocation errors make the cursor terminal, clear its cached pages and retain error context; no retry after a failed lookup. Source/handles/results/cursors retain their quota ownership until drop. Fixed standard shared controls retain the explicit M1 allocator-OOM limitation. Symbol lookup remains the existing fixed-state cold catalog scan; no new symbol-wide vector/cache is introduced.

Verification must include all frozen labels/IDs, exact a/A/non-UTF-8 handling, duplicates/unknowns, one-pass counters, label selections, block/string crossings, zero/tiny caches, two-page LRU, simultaneous cursor shared quota, predecessor restarts, source mismatch/change, injected read/allocation failure, lending compile-fail and final-owner cleanup. No OS-capped larger-than-RAM or throughput claim is made by this task.
