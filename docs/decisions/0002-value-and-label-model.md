# 0002 — Values, IDs and labels for the initial reader

Status: chosen M1 contract, not implemented. Evidence: format rules F06/F08/F13/F14/F17 and their oracle fixtures. This supersedes the architecture plan's illustrative API alternatives for the initial reader.

- `SymbolId` wraps `u32` with a private field; zero is the universe and positive IDs are validated against the source catalog. `UelId` wraps `NonZeroU32`, restricted to `i32::MAX` and the file's UEL count. `AcronymId` is a positive checked `u32` restricted to `i32::MAX`. Constructors are fallible; never clamp IDs.
- `Value` is a safe Rust enum: `NumberBits(u64)`, `Special(SpecialValue)`, or `Acronym { id: AcronymId, encoded_bits: u64 }`. `SpecialValue` has exactly `Undefined`, `NotAvailable`, `PositiveInfinity`, `NegativeInfinity`, `Epsilon`. Five-field data retains all fields in file order. Buffer accounting uses `size_of::<Value>()`, never an assumed stable enum ABI or hardcoded width.
- Tags 0–4 produce `Special`; tags 5–9 produce exact ordinary bits for 0, 1, -1, 0.5, 2. Tag 10 preserves its eight-byte payload in `NumberBits`, except a finite value >= `10.0E300` is classified as an acronym using the upstream positive ratio rounded to nearest integer, ties away from zero, after finite/range checks. `Acronym` keeps the original bits as well as ID. Nonfinite tag-10 payloads remain `NumberBits`; do not run floating-to-integer conversion on NaN/infinity. Missing acronym descriptions can be resolved lazily; raw scanning does not build an eager name map.
- An explicit `Value::number_bits()` accessor returns only ordinary bits, not lossy substitutes for specials. `as_f64(policy)` requires an explicit immutable conversion policy for special/acronym variants. The M1 default is lossless typed values; IEEE NaN/zero substitutions belong in later opt-in adapters. No global special-value remapping state is permitted.
- Metadata strings/labels are borrowed byte slices in lending views; retained copies require explicit budgeted ownership. UTF-8 conversion returns an error with context; lossy decoding requires an explicitly named adapter. No per-record label strings are created in the decoder.
- Symbol-name lookup folds ASCII case to match the modern upstream identifier contract. **Stored UEL IDs and bytes are always preserved.** Exact stored-label lookup/filtering is byte-for-byte and must distinguish `a` and `A`. A later native-compatible registration/find adapter may explicitly select upstream ASCII-folded behavior; it cannot silently replace exact matching. Task-003 registration tests demonstrate the distinction.
- Scalar defaults are generated from the exact F14 subtype tables only for zero-physical-row scalars. They are not additional on-disk records. Alias/universe cursors expose their resolved/synthetic values while preserving the requested symbol identity in errors and metadata.

This model favors clear semantics over an unsafe packed representation. Any later layout optimization must preserve these observable variants/bits, stay within the budget, and demonstrate a measured benefit. Writer normalization of signed zero/NaN/infinity remains a separate F13 compatibility rule; reading cannot erase bits merely because the current upstream writer would normalize that input.
