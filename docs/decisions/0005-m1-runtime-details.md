# 0005 — M1 runtime details and validation boundaries

The M1 implementation preserves the initial checked, lending, path-based reader design. The following details are explicit rather than hidden behind the original documentation-only blueprint.

- `ScanOptions::default()` has a concrete 64 KiB batch cap because it has no reader reference. `Reader::scan_options()` supplies defaults using that reader's configured maximum. For a custom maximum below 64 KiB, use the latter or set `batch_bytes` explicitly. Contradictory explicit caps fail; no silent clamping. This resolves the blueprint's impossible request for a reader-dependent `Default` implementation.
- Empty indexed symbols validate their terminator without allocating output columns. Other columns are allocated only after the first successfully decoded row. Output capacity uses actual Rust element layouts, selected fields, the configured payload cap, the remaining limit, and the 65,536-row ceiling. The cursor reserves its exact inline size (13,216 bytes on the tested target, checked against 16 KiB before construction); nested decoder/stream states are additionally conservatively charged. Empty projections retain bounded fixed state and no output payload.
- M1 streams metadata and permits cold linear lookup. No persistent page cache is implemented, so `metadata_cache_bytes` is a validated upper allowance with zero current cache occupancy. It is not eagerly reserved or an excuse for an unbounded map. Stream-backed metadata wrappers fit their stream's conservative 16 KiB state allowance; dedicated handles/domain/comment cursors have their own allowance. Metadata streams may retain their charged scratch until cursor drop. M2 owns reverse lookups, selections and independently oversized metadata/record tests.
- `truncated-block.gdx` also removes every metadata table after its truncated record block. `Reader::open` therefore rejects its out-of-file required pointers as `InvalidOffset` before a data stream can exist. This is an earlier F03 validation boundary than the artifact's intended isolated block error. A direct bounded record-stream test executes that same frozen artifact and gets the original intended `UnexpectedEof`; full-path integration separately asserts `InvalidOffset`. The artifact, manifest intent, and golden expectations are unchanged. Do not weaken pointer validation or defer it just to force a later error category.
- Source immutability checks happen at every physical fill and each nonempty scan call, including already-buffered and synthetic rows. EOF/zero-limit do not promise a new filesystem validation. Detectable truncation/mtime changes fail; every same-size concurrent rewrite is not detectable.
- All data-sized buffers are fallible and charged before allocation. Fixed standard shared-owner controls retain the stable safe-Rust OOM limitation recorded in decision 0003. Budget accounting is logical requested capacity, not RSS; there is no claim of OS-capped larger-than-RAM validation in M1.

Initial support remains the modern canonical v7 layout from the pinned writer, with uniform primitive endian order and optional domains. Mixed primitive orders, v5/v6, old producer heuristics and unknown extensions are explicitly rejected/omitted. No format compatibility was dropped based on an unmeasured speed claim. No raw record restart index, writer, selection engine, Polars/Arrow adapter, or parallel reader is introduced here.
