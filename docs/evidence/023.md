Each output is read completely by pinned native GDX and Rust. Native record
validation checks every key/value, ordered digest, UEL count/label bytes and
original IDs. Native metadata validation checks every label/ID and digest. Rust
streaming validators independently agree. Python calibrates the C++ recipe on
small deterministic inputs before large execution. Seed: `0x1640`, dimensions 20,
five ordinary value fields; labels are deterministic 63-byte strings. All input
and output SHA-256 identities are retained. Large artifacts are removed only after
complete validation/hash; compact reports remain.

Native GDX eagerly owns huge metadata. Its separate large-metadata reference
validator uses an explicit **16 GiB** AS cap, reaching 3.04 GiB RSS on
34M labels. That is not Rust containment. Every Rust writer/validator and native
record validator retains the 512 MiB cap. This distinction is explicit in each
measurement and does not substitute an uncapped Rust run for the required gate.

## Repeated phase benchmarks

AMD EPYC 9V74, Linux x86_64, Rust/Cargo 1.99.1, optimized builds. Complete compiler,
CPU/platform, overlay storage and binary identities are in JSON. The underlying
storage device is unavailable behind overlay. Three alternating native/Rust
repetitions use equal generated rows/values/digests, newly created outputs and
reused OS cache; no cold-cache or dedicated-runner claim. Numbers below are wall
seconds for encoding (records) or registration (metadata). Full min/max/stdev,
registration/encoding/finalization phases, whole-process CPU/RSS, output sizes and
hashes are retained per trial.

| Work | Rust median s | Native median s | Rust / native stdev s |
| --- | ---: | ---: | ---: |
| records / raw (1,000,000) | 0.143889 | 0.161819 | 0.009056 / 0.009437 |
| records / zlib (1,000,000) | 0.317317 | 1.448750 | 0.022999 / 0.024794 |
| metadata / raw (250,000) | 0.797887 | 0.153845 | 0.034055 / 0.049880 |

The representative raw encoding median meets the initial native-equivalent
throughput target on this workload; do not extend it to all workloads/platforms.
Rust's level-1 miniz compression and native zlib default level 6 differ. Their
1M-row outputs are 11,011,922 / 10,575,882 bytes; the timing is an option/size
tradeoff, not an equal-level codec speedup. Native gmsstrm.cpp calls zlib compress().
Rust finalization includes sync_all and bounded disk replay; native gdxClose has
no equivalent durability promise. Finalization timings are separate and must not
be presented as equal policy.

Bulk registration remains 5.19x slower than eager native registration at 250000
labels. Investigation reduced fragmented emission with a fixed checked 126-byte
record packet and tiny I/O with a constant journal page. The page reuses the
existing admitted append buffer; an initial extra allocation broke a one-MiB
compressed fixture and was replaced without raising its cap. The remaining
metadata gap reflects sorting/checksummed disk state and replay; it is a documented
performance limit, not a claim of global throughput parity. Incremental name and
reference scans may remain quadratic. Allocation counts were not instrumented;
tracked capacities, RSS and actual OS limits are reported separately.
