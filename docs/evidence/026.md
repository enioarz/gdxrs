## Implemented behavior

`MappedUelId` is a distinct zero-capable caller ID, while raw `UelId`s stay
one-based. Writer registration consumes labels and caller IDs without retained
token arrays, preserves existing/first-encounter raw IDs, and builds a sparse
immutable bidirectional index. Mapped symbol writes translate IDs and externally
sort through task 024 into raw GDX order. The session map is not stored in GDX.

Reader maps are explicit source-bound owners, returned before fallible index
registration. They retain cleanup ownership after errors. Mapped cursors prescan
and sort complete rows into caller order, returning borrowed fixed rows with
both mapped and original raw keys plus typed values. Missing mappings are errors
by default; explicit SkipRecord counts discarded rows. Limits apply after mapped
ordering. Errors after output are sticky, preserve secondary cleanup errors,
and never replay prior rows. Raw APIs and raw streaming behavior are unchanged.

Both directions share one existing checksummed fixed-frame Store and reuse the
existing spill format. Lookups binary-search sparse frames; an i32::MAX caller ID
costs one entry, not a huge dense allocation. Windows uses the physical ordinal
read path to preserve integrity when NTFS timestamps lag. The index, staging,
dictionary and row merges use one root and the existing journal/sort quota halves.
One index slot is deducted from the merge handle allowance. At least seven
available handles are required; another retained store consumes another slot.
Historical handle peaks now survive explicit cleanup. No dependency, unsafe
code, GDX wire-format or private spill-format change.

## Independent qualification

Seven mapped author cases cover raw default/minimal/all, zlib default/all, and
raw/zlib generated 2048-label dictionaries. Both native and Rust authors are
checked by complete raw metadata/UEL/value streams against independent recipes.
For those files, 104 complete mapped-read streams compare both implementations
to explicit expectations, including original raw keys, mapped lexicographic
order, zero/sparse IDs, all value fields, strict alias domains, scalar/default
behavior and missing-record counts. Generated maps permute raw order and have
sparse caller IDs; tiny-run tests force multiple merge passes. Native references
run under the existing process isolation policy.

Native zero IDs, idempotent assignments and inverse collision overwrites are
independently probed. Rust accepts identical repeated pairs and explicitly rejects
either-direction ambiguity. The isolated native negative-ID probe aborts on Linux
with signal 6 / "double free or corruption (out)". Pinned source shows SetMapping
writing PMap[F] without a negative bound check. That reference limitation is
recorded rather than counted as successful negative-case parity. Rust rejects
negative and wider-than-i32 IDs before registration on every qualified platform.
No enormous sparse ID is passed to the native dense allocator. Native registration
case folding remains the documented task-025 difference; mapped native comparisons
use unambiguous labels. See decision 0020 for the deliberate policy differences.

The first mapped oracle extension changed the frozen generator's identity and
correctly failed M0 plus three tooling integrity checks. The frozen driver was
restored byte-for-byte. A separate `tools/mapped` executable reuses its pinned
helpers without modifying it, with separately recorded source/executable hashes.
Fresh M0 qualification passes. No golden stream, fixture manifest, generator hash,
assertion or quota was updated to bypass that failure.

## Resource observations

Generated authors register/write 2048 labels and rows without an input-sized
token array. Generated readers map and completely validate the same files.
All use a 1 MiB library root, 16 KiB runs and seven available scratch handles.

Values are bytes except handles. These are charged capacities, not RSS or OS
containment. Hardware/compiler/storage details are retained in the accompanying
smoke report. No throughput benchmark, equal-level compression speedup or mapped
larger-than-RAM claim follows. Task 031 remains the general-input OS/RSS/throughput
acceptance gate. Mapped reads currently sort even identity/monotone maps, and
checked table lookups can require O(log N) reads per key.

## Remaining scope

This task implements bounded immutable bijections, not incremental native map
mutation, auto-expansion, ambiguous inverse overwrites or direct mapped-to-label
convenience. The API inventory records those distinctions. Writer registration
retains task 025's occurrence-count limit. Mapped output is fixed rows with a
bounded prescan batch; projection/filter/batch conveniences are not added. Close
is explicit and Drop is best effort. Existing allocator/publication/durability
limits remain. Tasks 027–031 stay pending; task 027's domain/error streams are next.
