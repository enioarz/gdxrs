## Behavior and review findings

Existing UELs can be renamed before or after closed symbols without changing raw
IDs, registration order, caller-map pairs, record keys or typed values. A bounded
journal rewrite charges original/replacement extents and relocates membership
anchors. This prevents the key review risk: a label-length change shifting disk
membership offsets while strict validation still needs completed set contents.
Only one contiguous membership group is tracked at a time; GDX data positions
are preserved. The task-028 acronym rewrite reuses this helper.

Late comments and repeated relaxed display domains remain independent from
strict domains. Original strict alias IDs/checks remain intact while display
names take precedence in the relaxed table, matching native. New safe edit phases
are explicit; schema identity/new registrations/strict definitions remain frozen.
Accepted nonzero set-text levels now serialize the actual has-set-text flag;
alias/non-set/empty flags remain false. Native SetHasText is a query, not a setter.

Signed text-node state supports slot 0 and sparse i32::MIN/MAX values without
allocating by the node number. Assignment succeeds while current node is zero;
nonzero nodes cannot be overwritten. Source confirms nodes are not part of GDX's
set-text serialization. Writer/read-session assignments disappear after reopen,
and the complete native/Rust expectations verify that behavior.

Read metadata sessions retain sparse label overrides/nodes on disk, preserving
source bytes/IDs and other views. Direct/inverse mapped label queries and highest
caller-ID information reuse sparse indexes; zero is distinct from no mapping.
Explicit mapped/session joins check source identity. Fallible UEL visits and
mapped-order domain callbacks preserve original IDs, acknowledgment counters,
secondary cleanup errors and retry ownership. Failures are terminal and never
implicitly replay prior output. Maximum-length queries explicitly stream catalogs
or scan records with fixed 20-axis state; ordinary scans do not invoke them.

## Resource and compatibility limits

Author cases use a 1 MiB library root and eight configured scratch handles. Peak
charged root is 527656 bytes raw / 986587 zlib; conservative peak scratch is 2107
bytes, and per-job conservative handle peak is seven. Context peaks are at most
527464 bytes raw / 587015 zlib, with a per-job peak of seven; the separate view
uses one journal handle. These are root charges and per-job metrics, not RSS or
an aggregate process FD bound. Each explicit read view has its own scratch-job
quota and shares Reader memory. Old history remains charged until close.

Journal rewrites and metadata/history lookups may be quadratic or worse under
repeated operations. Domain visits explicitly scan/sort; length queries explicitly
scan. No throughput/OS/RSS claim follows. Task 031 retains general-input acceptance.
Append is task 030. Full C ABI, implicit read catalog/domain-map expansion, mutable
caller maps and identity/schema replacement remain unsupported as documented.
Tasks 030–031 remain pending; task 030 is next eligible after 029 qualification.
