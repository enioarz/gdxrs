## Findings, corrections and author review

Review identified three clean-checkout/portability issues before claiming support:

1. The CLI eagerly imported modules using Unix `resource`, preventing Windows
   reader checks from starting. It now imports only the selected command's tools.
   Two Python dispatch tests prove the portable reader avoids Unix-only modules
   and unsupported Windows scale commands fail before resource import.
2. Cargo tests assumed a pre-existing `.work` parent. Helpers now create it; no
   prior setup/Python execution is needed. All four clean-checkout jobs prove it.
3. Native Windows clean-checkout Rust tests passed immediately, but full validation
   correctly failed on a warnings-denied `unused_mut` in scratch directory creation:
   only Unix directory permission configuration mutates that builder. The fix uses
   a cfg-scoped mutable shadow, retaining Unix mode 0700 and Windows behavior. No
   warning is suppressed and no validation/assertion is weakened.

The first Windows failures remain failures (runs 40221362923 and 40221702648).
A diagnostic-only intermediate run was superseded/cancelled by newer revisions.
Run 40222089919 then passed the debug matrix; final run **40222541485** adds and
passes optimized release tests on every platform. CI stores a bounded failure
annotation as well as complete log/report artifacts, making remote failures
reviewable without assuming a particular artifact-download network path.

Author review checked action/source pins, actual host and merge-tree identity,
feature/corpus counts, Unix import isolation, UTF-8/newline behavior, scratch
permissions/publication invariants, Windows handle closure, concurrent source
positions and truthful qualification scope. This is author review plus actual
native CI, not a claimed independent review or new cross-platform OS memory proof.

Local Linux checks also passed: clean archived checkout Cargo tests, focused
platform tests, reader-check, runner dispatch tests and M0 aggregate validation
(including **41 Python tooling tests**). Retained local report references are in

## Scope and remaining follow-ups

Functional support is qualified on the exact native targets/OS runners above.
Older OS releases, Windows ARM64/32-bit, network/removable filesystems and arbitrary
filesystem ACL/locking configurations are unqualified. Spill scratch must still
support same-filesystem hard links and use a trusted private namespace; errors
remain visible rather than silently falling back to another storage model.

macOS/Windows multi-GB OS memory containment and throughput measurements are not
executed here. Existing Linux task 016 evidence remains the scale/performance
qualification; it is not relabeled as Windows/macOS RSS evidence. The same logical
library budget/failure tests do pass on all native hosts.

Task 017 is complete; no native reader compatibility blocker remains before
**M3 sorted-writer specifications**. Keep this matrix green as the core evolves.
