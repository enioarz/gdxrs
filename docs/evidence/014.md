## Delivered

`spill_sort(&SpillOptions)` shares the reader's root memory quota and creates an exclusive private scratch directory. A fallible fixed-capacity record buffer sorts exact byte-label/opaque-u64 tuples in place; duplicates survive. Consuming finish creates bounded-fan-in merge passes, with explicit 32 KiB read/write buffers. Contiguous numeric run ranges replace an in-memory run/path list; at most fan-in heads/readers and one output writer coexist. Input runs close and are deleted only after their replacement finalizes.

Private versioned runs validate header, length ≤255, tuple order, count, FNV-1a-64 checksum, trailer and exact EOF. Final returned count must equal accepted input. Publication flushes/syncs/closes the partial run, creates an exclusive hard link and removes the partial name. No rename-overwrite fallback exists. Temporary logical-byte quota is reserved before buffering/writing and run-handle quota before opening; live input/output overlap counts. All variable data buffers are fallible/root-charged; controls/path scratch have bounded conservative reservations.

The lending output returns complete entries, stays terminal after errors, and marks statistics complete only after validated EOF and successful cleanup. Cancellation/early close is explicitly incomplete. Cancel/close surface cleanup errors and permit cleanup retry; Drop is best effort. A bounded secondary cleanup cause and Display marker preserve the original operation error/cause. Directory ownership, format, quotas and failure contracts were recorded before implementation in [decision 0008](../decisions/0008-spill-runs.md).

## Measurements and review

The focused valid merge observes **264-byte** in-memory records, **six** passes, **80** published runs, peak **three** run handles, **5,338 logical temporary bytes** and **214,536 root-requested bytes**. At EOF run handles/temporary bytes are **0**; after the final source-owning cursor drops, root requested bytes are **0**. This is logical accounting, not RSS or physical filesystem-block usage. Path/input/test instrumentation overhead is scoped as documented; no OS memory cap or large workload was run here.

Author review checked admission before writes/opens, exact-capacity buffers, in-place sort, arithmetic run-range invariants, handle/FD drop order before cleanup, pending publication ownership, full record framing/integrity, accepted-input versus returned counts, terminal errors and secondary cleanup preservation. Fixed shared/path controls retain the recorded safe-stdlib allocator-OOM exception. Runtime file lengths/IDs never drive allocation.

An initial focused run caught the completion flag not being set after successful EOF; code now sets it only after total-count validation and cleanup, and cancellation tests keep it false. Review additionally preserved filesystem metadata I/O causes, bounded canonical parent/path capacities, made repeated cleanup idempotent, and added partial-write, independent wire-vector and valid-but-missing-input corruption cases. All final checks pass; no threshold/fixture was weakened. This is **author review**, not independent M2 release approval.

Limits are per spill session for temporary bytes/run handles; memory is source-wide. Multi-job integration must budget the sum of its session limits. Scratch parent/namespace must be trusted and unchanged by other actors; same-directory hard links are required. Drop cannot report failures, crash recovery is absent, and FNV is not authentication. Filesystem inode/block overhead, runtime descriptors and allocator/RSS headroom are outside logical counters. No actual filesystem exhaustion, native non-Linux qualification, Rust throughput speedup, spill-backed large-label/domain integration or OS-capped out-of-core release is claimed.
