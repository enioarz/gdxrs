## Implemented behavior

A fixed per-Writer policy interprets float inputs through exact sentinel bits on
all sorted/unsorted/mapped/string/deferred adapters. Typed writes bypass it.
Unmatched IEEE bits are preserved by default; native NaN/infinity/negative-zero
normalization requires explicit selection. Invalid write maps, value conversion
or references terminate the transaction and block publication. Conversion errors
cancel external sorters before parent cleanup and retain secondary diagnostics.

A separate per-reader ValueSession produces a ProjectedValue containing the
original typed value, numeric projection and acronym-mapping provenance. Exact
conversion permits unchanged ordinary values only; AllowLoss explicitly converts
tagged identity to one float. Internal/read special maps stay separate, read
collisions require an explicit option, and special reset preserves mappings and
next IDs. Acronym-to-NA uses internal NA even if read-only NA differs, as native does.
Core scans/defaults/filters and other sessions stay unchanged.

Explicit, identity and automatic acronym assignments use a bounded disk journal,
not a RAM map. Original IDs remain available; checked next IDs advance once per
new assignment. Bijective policies reject explicit/automatic collisions; checked
canonical values reject float overflow. Mappings remain stable within an epoch;
explicit reset starts a new epoch and leaves prior journal bytes charged until
close. Source acronym information is streamed into fixed-size name/text results;
unknown source entries return None without mutating the catalog. No implicit
whole-table load or synthesized metadata is hidden in projection.

Writer update_acronym changes registered name/text before freeze, preserving ID
and ordinal. It checks names/collisions, streams a replacement metadata journal,
charges both live extents and buffers, syncs, closes both handles, renames and
reopens the owned journal. Failure blocks publication and retains cleanup/retry
ownership. Lazy read-journal initialization similarly returns its owner before
fallible allocation; fault tests preserve the primary and secondary errors.

## Native expectations and differences

The separately hashed tools/values helper links pinned GDX
`9e2a8c8932412010cd7d2f94727d1740143bf3da`; frozen driver, generator, isolation
policy and pins are unchanged. Ten author cases cover raw default/minimal/all and
zlib default/all for ordinary custom sentinels and bitwise NaN/signed-zero/IEEE
sentinels. Independent complete expectations include every metadata/UEL/acronym
entry and all five fields of every row, verified in both author/read directions.
Eighty complete projection streams cover native and Rust authors, identity,
custom read maps, explicitly lossy read/acronym-to-NA projection, resets, explicit
remaps and lazy next IDs. Original typed values are checked alongside projections.

Native probes verify duplicate write-map rejection is atomic, duplicate read-map
acceptance, reset behavior, acronym metadata rename, explicit target collision
rejection and overflow-to-infinity products. Native lazy allocation reproducibly
maps two different original IDs to the same automatic target; Rust rejects it
terminally. Native AcronymValue can overflow for a valid i32 ID; Rust's checked
canonical constructor rejects that instead of silently producing infinity.
Known unsafe native ordinal-bound paths are identified from source and are not
invoked or claimed as successful negative-case parity. Native call-state and
implicit unnamed/late writer metadata mutation are explicit exclusions.

## Resource scope and remaining work

Fixed author cases use a 1 MiB library root and six configured scratch handles.
Peak charged root is 263280 bytes for raw and 722211 for zlib; metadata update
peaks at two handles and 171 conservative temporary bytes. Projection peaks are
at most 319176 bytes for raw and 384711 for zlib, with one live journal handle.
These are charged capacities, not RSS. Each explicit reader session has a separate
scratch-job quota under the shared memory root; only the existing journal half
is used. Caller-retained results use caller memory.

Mapping searches may be quadratic across many active assignments; metadata
information scans and streamed rename rewrites are explicit costs. Assignment
order follows explicit project calls, and unprojected fields allocate nothing.
There is no throughput parity claim. Task 031 retains general-input OS/RSS/scale
acceptance. Tasks 029–031 remain pending; task 029 is next eligible after 028 passes.
