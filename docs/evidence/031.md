## Performance findings and disposition

Three alternating trials per producer use fresh outputs and reused OS caches.
Every benchmark output passes both complete validators before its SHA-256 and
retirement. The native reference is an explicit eager C++ vector/std::sort/sparse
map composite plus native GDX registration/encoding, not an out-of-core reference
or native legacy adapter internals. It has a separate 16 GiB cap. These cost and
memory differences are part of the comparison.

Median full worker wall seconds (validation/hashing are separate):

| --- | ---: | ---: | ---: |
| unsorted / raw | 1,000,000 | 2.332 | 0.457 |

| mapped / raw | 1,000,000 | 55.274 | 0.609 |

The >10% investigation threshold is exceeded by the raw general-writer families.
The provisional general throughput target is **not met**. This does not overturn
M3's previously measured sorted raw workload result; the M4 wide recipe changes
many axes and requires external sorting/adapter work. No general native throughput
parity is claimed.

The observed one-page lookup churn was addressed with an optional, root-charged
16-way cache and snapshot-scoped searches. Exploratory 16,384-row mapped buffered
reads fell from 66,265,898,193 to 117,912,256 bytes (not physical disk bytes);
wall time fell from about 5.6 to 2.2 seconds with matching native/Rust digests.
Those exploratory sources were uncommitted, so this is diagnostic evidence only;
the acceptance and timing tables above use the committed snapshot.

Remaining costs are explicit. At 1M rows, string remapping/staging has a 9.401 s
median; mapped ingestion, including translation and initial run creation, takes
52.769 s. One mapped trial spends 46.02 s user CPU and 7.67 s system CPU while
performing about 500 MB of buffered reads. Disk-backed binary search, repeated
checked frame decoding and registration/remapping passes remain much more
expensive than the eager native tables. A future bounded translation index or
checked fixed-frame decoder needs separate measurement; removing checksum,
source-integrity or physical Windows ordinal checks is not an accepted shortcut.
Bulk registration is the supported large-dictionary path; incremental scans may
still be quadratic.

Phase observations and dispersion are retained separately for registration,
remapping/staging, ingestion/run creation, merge preparation, replay/encoding,
copy and finalization. They do **not** partition all process wall time: deferred
dependency/spool traversal and startup/sampling contribute residual time, recorded
in `performance_analysis`. Native string lookup is included in ingestion rather
than reported as a zero-cost remap. Full wall medians above retain those costs.
Rust finalization includes sync_all; native gdxClose gives no equivalent durability
promise. Rust miniz uses level 1, native zlib default level 6, so the compressed
result is an option/size tradeoff and not equal-level codec parity.

Self-review found and fixed historical handle peaks incorrectly combined with a
later spool; admission limits remain unchanged. Focused tests cover dirty cache
eviction/writeback failure, allocation accounting/release, corruption, changed
extents, snapshot checks, inherited duplicate-label semantics, shared append roots
and cached variable frames crossing pages. Cache defaults retain the previous
single-page footprint and existing 1 MiB tests. Production dependencies are unchanged.

The scale/correctness/API findings are closed for the measured scope; the slower
adapter throughput is a documented limitation and future optimization work.
Legacy ABI/call-state, slice-shape and external-converter exclusions remain M8.
This record is an implementation self-review, not independent approval. M5 should
begin only after the M4 change is reviewed/merged; it is not started here.
