# Task 031 — M4 acceptance work in progress

M4 is **not qualified yet**. The required growing, independently oversized runs,
four-platform CI and findings disposition remain open. Smoke is explicitly
insufficient. No independent review is claimed.

The [API audit](../m4-api.md) and [decision 0025](../decisions/0025-m4-acceptance-cache.md)
define the current scope, exact native exclusions, fixed thresholds, reference
cost differences and optional cache design. The frozen M0 inventory, generator,
fixtures, checksums and M2/M3 thresholds are unchanged.

Exploratory uncommitted-source pilots checked all six recipes at 16,384 rows
(1,024 dictionary labels) under the 256 MiB root / 512 MiB Linux process cap.
Complete Rust/native ordered record and UEL digests and diagnostic digests matched.
They exposed about 66 GB of buffered mapped lookup reads for 16,384 rows. A
root-charged cache reduced the mapped pilot wall time from approximately 5.6 to
2.2 seconds. These are diagnostic observations, not committed-source acceptance
or general performance claims. Reports remain under `.work/031-pilot-results.json`
and `.work/031-cache-pilot.log` in the working environment.

The implementation adds focused dirty-eviction, accounting/release,
allocation-failure and changed-source regressions; a calibrated native composite;
and fail-closed tooling tests for mandatory families, thresholds, diagnostics,
required API entries and OS/root containment. Final exact results and measured
source revision will be recorded after validation.
