[Decision 0034](../decisions/0034-measured-scan-policy.md) defines the contract;
[the API guide](../m6-policy-api.md) describes `ScanPolicy`, `ScanMeasurements`,
`ScanPlan` and `Reader::scan_planned`. The policy is a pure deterministic function
over caller-supplied measurements and caller-specified limits; it performs no I/O,
never scans a source to choose a plan, and never builds or opens an index
implicitly. Exact filters, global limits, source trust and acknowledged progress
are preserved across every choice through one `PlannedScan` surface.

## Deterministic policy tests

Twenty new unit tests (`src/index/policy_tests.rs`) cover explicit overrides
(including worker-limit rejection), head/zero and small-input serial fallback,
strict-reopen charging, poor-pruning and admission-pressure rejection, tie order,
break-even computation, invalid policy/measurement rejection, and dispatch
equivalence: identical ordered key/value digests across serial, indexed and
parallel execution of all/selected/head queries on a frozen fixture, plus the
never-implicit-open error paths.

## End-to-end comparisons (held-out representative inputs)

Each small case generates a fresh native source, validates it against the pinned
oracle, measures serial, explicit build, strict reopen, warm indexed full/leading
and 2/4/8-worker parallel full scans under one 256 MiB root and an enforced,
self-checked 512 MiB Linux RLIMIT_AS, feeds those measurements to the real
`ScanPolicy`, then executes the planned scan for all/leading/head/zero shapes.
Planned digests equal the native/serial/indexed digests; head/zero always choose
serial; all/leading choices stay within 1.5× of the measured best. Medians
(records 4M, this 5-core host): serial full 1.178 s, build 2.073 s, strict reopen
1.973 s, warm indexed full 0.835 s, warm leading 0.002 s, 8-worker parallel full
1.813 s. Parallel full scans are slower than serial here, so the policy correctly
admits serial for full scans (admission-pressure guard) and indexed for leading
queries. Root peaks ≤ 29,377,280 bytes, wait4 RSS ≤ 14,671,872 bytes, sampled
descriptors ≤ 6 including stdio. A serial fallback is not claimed as parallel
benefit; no speedup is claimed on this host.

## Scope and limitations

One measured comparison per case/shape; dispersion comes from the smoke/small
pair and task 036's trials. Linux RLIMIT_AS/RSS containment and timings only; not
cross-platform. Policy inputs are caller-supplied measurements — there is no
unmeasured universal threshold and no hidden cache. Writer/label-page/M3/M4/M5
scale gates were not rerun; the only production change is the new `index`-feature
policy module, and writer-check/label-pages-check/parallel-check/m6-profile pass
at this revision. No independent review, automatic M6 release or general
throughput parity is claimed.
