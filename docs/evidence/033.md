## Delivered contract

`Reader::index_builder` returns an owned explicit builder before filesystem mutation.
One serial record pass streams fixed 1024-byte checkpoint pages and a 16-way paged
directory. Record/decoded-byte strides partition even long first-key groups. Each
interval retains complete restart state, half-open raw ordinals and per-axis bounds.
No checkpoint collection, in-memory root directory or whole-file mapping is used.
All controls, pending pages, digest I/O, cache and returned objects share one root.
Whole-file extent includes all directory pages; source plus sidecar require two
admitted handles. Publication is sync/close then atomic no-clobber or explicit
replacement, with retained cleanup ownership, secondary diagnostics and abort retry.
Replacement protects existing GDX/non-sidecar targets; pathname ownership is required.

Off does no index work. UseIfValid never builds and distinguishes missing/rejected
caches from source/access/resource errors. Strict reopen hashes the whole source,
then regenerates every checkpoint/summary from the symbol before exposing Ready.
This source-derived proof rejects forged tuples/summaries even if every unkeyed
checksum is recomputed. Later page access verifies a path against the regenerated
session root; it does not rehash the source or scan the directory. Integrity failures
are sticky, with no implicit restart after output. There is no trusted-cache shortcut.

## Independently oversized directory

`python tools/dev.py index-check --profile scale` passes at the committed revision.
Both growing cases build and strictly reopen under an 8 MiB library root and
self-verified Linux RLIMIT_AS soft/hard 64 MiB caps. The source is independently
native-generated and fully native-validated. Source hashes before/after must match;
Python independently verifies the header's SHA-256. Reopen compares every canonical
page against source replay, and sampled checkpoint suffixes check exact keys/value
bits against the native generator's mathematical recipe. Artifacts are retired
only after full validation and source/index hashing.

| Intervals | Source bytes | Directory bytes | Total index bytes | Build / reopen peak RSS bytes |
| --- | --- | --- | --- | --- |
| 300,000 | 37,865,998 | 20,482,048 | 327,683,072 | 11,923,456 / 11,923,456 |
| 1,200,000 | 151,275,470 | 81,923,072 | 1,310,724,096 | 11,923,456 / 11,923,456 |

The largest directory itself exceeds the enforced process cap, independently of
the data pages. The whole index exceeds four times that cap; the source also exceeds
the cap. Root peaks remain exactly 205,560 build / 157,456 reopen bytes in both
cases. Reported RSS is the conservative wait4 high-water mark; sampled post-exec
RSS/virtual memory and handles are retained separately. Growing RSS stays within
the fixed 8 MiB allowance. A fixed 16-level pending directory and one-page read
cache avoid allocation proportional to interval count.

Largest-case build: source digest 0.491 s, record/page generation 11.799 s, total
worker 12.743 s. Strict reopen: digest 0.482 s, full replay/page validation 10.015 s,
total worker 10.521 s. These are one-run containment measurements with uncontrolled
cache state, not throughput parity or cold/warm acceleration acceptance. Smoke
workers (1,024/4,096 intervals) also passed during development; qualification above
uses the final committed sources and growing independently oversized directory.
