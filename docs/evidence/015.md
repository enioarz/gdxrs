## Deliverables

[Decision 0009](../decisions/0009-large-labels-domains.md) specified APIs and
ownership before implementation. `src/large.rs` implements the request builder,
lending exact-byte sort/merge join, disk-selection preparation and observed-domain
extraction. `src/selection.rs`, `src/scan.rs` and `src/spill/` integrate fallible
membership probes with existing source/symbol-bound selection, batching, projection,
accepted-row limits, temporary runs and cleanup. No dependency was added; Cargo
manifests/lockfile, frozen corpus and original M0 review artifacts are unchanged.

Requests carry original zero-based ordinals and stream in `(label, ordinal)` order;
unknowns retain None and duplicates remain distinct. Original one-based UEL IDs
survive sorting. Membership consumes a fresh complete lookup and intersects the
existing base selection on any original dimension. Its private fixed-frame run is
fully validated before positioned binary probes; no in-memory dictionary, offset
vector or universe bitmap is created. Domain extraction externally sorts and
deduplicates observed `(original dimension, original UEL ID)` pairs from the exact
selected/limited row stream. Lookup and domain preparation are blocking.

Lookup splits total temporary bytes/run handles into three equal session shares;
merge fan-in is reduced to fit each share. At most three sessions coexist, and
memory from all sessions competes for the same source root. Explicit close/cancel
surfaces cleanup failures; selections require exclusive disk ownership to close.
Closing makes a selection empty. Consuming-finish cleanup failure can require
manual recovery under the caller-controlled scratch parent. Drop is best effort.

## Author review and remaining scope

Author review checked source identity before conversion, complete UEL/input
validation, first-ID handling for duplicate stored labels, original request ordinal
preservation, fallible fixed-capacity allocations, three-session quota composition,
closure/handle drop order, partial-result semantics and cleanup retries. In-memory
base constraints run before disk probes to avoid unnecessary scratch I/O. Layout
guards cover wrapper control allowances. Review corrected the default fan-in
planning for split handle quotas, prohibited partly consumed lookup conversion,
and distinguished completed integration from pending scale qualification in runner
reports. Initial focused checks also caught a test fixture filename and a
warnings-denied style issue; both were fixed without changing expectations or
thresholds. This is author review, not independent release approval.

At most one disk clause is supported per selection. Membership binary probes use
positioned reads without an offset directory/cache; they are an exact bounded
baseline and may be slower than in-memory sets. Preparing a lookup sorts the full
UEL table. Trusted private scratch namespaces and same-directory hard links remain
required; FNV checks are not authentication or crash recovery. Standard fixed
shared-owner allocation/OOM limitations remain as previously recorded. Independent
jobs do not share a global disk/descriptor cap.

No OS memory cap, peak RSS, independently oversized UEL table, >4 GiB case,
throughput improvement, native non-Linux execution, GDX writing or Polars
integration is claimed. **Task 016 is next eligible** and remains the required M2
out-of-core qualification gate.
