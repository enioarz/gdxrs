## Changes and findings

Finalization validates completed counts, symbol/data positions and set-member
extents, then emits canonical symbol, set-text, UEL, acronym and optional relaxed
domain tables by bounded journal replay. It checks metadata offset ordering before
patching only the uncompressed major index. Existing flush/sync/close/exclusive
publication and retryable cleanup ownership are retained. File-close failures
remain unreportable through std File drop; directory entries are not synced.
No new production dependency, unsafe code or full metadata/record collection.

The combined fixture exposed an incorrect earlier assumption: native GDX retains
K -> J -> I, including K's referenced alias ID J and description `Aliased with J`.
Rust previously wrote K -> I. Alias definitions now validate the chain and retain
the original resolved reference, matching the strict-domain identity rule. The
forward A -> B -> I regression, corrected from the old flattened expectation,
was run against the previous serializer: one executed test failed with actual 3
(underlying I), expected 2 (referenced B). It now passes in all feature suites.
This supersedes task 020's historical claim that definitions flatten natively.
The fixture correction is supported by the independent native recipe, rather
than changing expectations to match Rust output.

The new native recipe initially deduplicated `a`/`A` while reopening registration
per U directive. Its resulting UEL table could not support the authored IDs. The
new shared authoring fixture uses distinct `a`/`C`; frozen case-distinct-label
fixtures and all existing Rust-written registration tests remain enabled and
unchanged. The Rust core retains exact label bytes/IDs.
