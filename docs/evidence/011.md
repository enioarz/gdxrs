## Resource audit and review

All production dynamic data buffers use `budget::Buffer`: checked exact layouts, root reservation before `try_reserve_exact`, capacity verification and bounded push. The source shares one atomic budget across handles/cursors. Fixed source/handle/domain/comment state is conservatively charged; stream-backed metadata wrappers fit their stream state allowance. Scan inline state is charged separately and verified below 16 KiB. Decoder/stream state and codec scratch receive additional conservative charges; byte buffers are 32,768 decoded / at most 65,535 encoded. No persistent metadata cache is allocated; its configured cap is a future allowance, not hidden eager storage.

Measured layouts: `ScanCursor` **13,216**, `Decoder` **12,008**, `Value` **16**, `UelId` **4**, codec **10,504** bytes. The fault test with simultaneous prefix/limit cursors peaks at **346,510 logical requested bytes**. This is library capacity accounting, not RSS. Quota rejection, synthetic allocation failure, partial-error cleanup, borrowed-buffer reuse and exactly-once full-owner drop are executed. Fixed safe `Arc`/`Box` controls retain standard allocator-OOM abort behavior; see [decision 0003](../decisions/0003-m1-advancement.md).

Author review at the tested revision examined public borrowing, file/handle identity, twenty-key/five-field bounds, actual capacity calculations, alias hop limits, exact limits, field framing, error terminality, codec checksums and allocation ownership. Findings resolved: reader-specific defaults now have `Reader::scan_options()`; output allocation is lazy for empty symbols; buffered truncation checks happen at scan boundaries; final ownership release is tested; released M0 evidence is preserved without applying its hash to M1. [Decision 0005](../decisions/0005-m1-runtime-details.md) records those choices and the truncated-block artifact's earlier public InvalidOffset versus isolated stream UnexpectedEof. No expected artifact or assertion was loosened to conceal that validation order. This is **author review**, not an independent M1 review.

Remaining scope: M2 selection predicates, exact large-label request lookup and independently oversized records/metadata under an OS cap; M3/M4 writers; later indexes, parallelism and Polars. No Rust throughput/speedup, native Darwin/Windows/big-endian-host, >4 GiB file, exhaustive fuzz campaign, cache eviction, or OS-capped larger-than-RAM claim. The next implementation milestone is **M2**, requiring its own numbered specifications.
