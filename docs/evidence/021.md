## Deliverables and checks

[Record contract](../decisions/0015-sorted-record-writer.md) and
[src/write/records.rs](../../src/write/records.rs) expose `KeyBounds`,
`Writer::begin_symbol` and the borrowing `SymbolWriter::{write, finish}`.
Registration freezes before records. The writer checks dimensions, arity,
registered ID ownership, bounds, strict lexicographic order, scalar multiplicity,
set-text/acronym references and signed v7 count limits before accepting rows.

Headers use unknown count -1 with supplied inclusive bounds or conservative
0..i32::MAX bounds. Verified first-change/delta keys, one/two/four-byte offsets,
common-value tags, ordinary binary64 bits, typed special values and acronym
encodings stream through the existing bounded codec. Symbol completion retains
position/count information in the metadata journal; the final catalog uses those
counts. Untouched symbols retain task 020's empty/default behavior.

Strict-domain metadata retains referenced aliases. Membership resolves the
underlying one-dimensional set (or universe), using fixed 19-byte checksummed
member frames in the existing quota-controlled journal and binary search over a
completed set's extent. The symbol retains at most 20 domain descriptors; no full
set is loaded. Non-universe domain sets must finish before dependent symbols
begin. Alias definitions have no own record stream. Each symbol is written once.

Dropping an unfinished symbol terminates the transaction. A parent active flag
also prevents finalization after `mem::forget`. Failed rows, scratch/output
failures and root-admission failures prevent publication; existing retryable
cleanup ownership remains in force. No new dependency or unsafe code is added.

The nine focused unit tests and public API integration test cover dimensions
0/1/2/20, width transitions, ordinary negative zero/NaN bits, short three-byte
writes, alias-domain success/failure, absent/empty/corrupt membership, bounds,
foreign keys, invalid arity/values, duplicate/out-of-order/scalar rows, repeated
symbol starts, abandoned/forgotten symbols, count overflow, output/scratch faults,
root exhaustion and shared-reader root release. These supplement the existing
encoder and transaction fault tests; they do not replace those gates.

## Independent interoperability

`examples/create_records.rs` is a fixed small tooling recipe, retaining only 700
caller-owned UEL tokens and a bounded number of symbol tokens. Its Python
expectation in `tools/writer_records.py` is authored independently of Rust output
and the Rust reader. `writer-check` compares complete native GDX and Rust dumps
against it, rather than comparing counts alone.

Each case contains 700 UELs and 45 symbols, with 7045 stored physical records and
7768 public records including universe, aliases and default scalar views. It
covers every symbol kind, variable subtypes 0–9, equation subtypes 53–59, all five
fields, empty defaults for every subtype, dimensions 0/1/2/20, set text, strict
alias/universe domains, special values, acronym 7 and negative zero. A 7000-row
symbol crosses multiple decoded 32 KiB blocks. Independent Python decoding also
asserts data preambles/count sentinels, terminators, exact width transitions
255/256/65535/65536 and first-change/compact/explicit delta bytes.

All five cases pass: raw default/minimal/all and zlib default/all. Raw files are
76565 bytes, SHA-256 `19f6f06440ed736810c19276bb80ae72b653a03a3aa084bf2a21d64942d09188`;
zlib files are 3841 bytes, SHA-256
`7128adc756803227f081d1702842d642baefb84a02ccfb85c452ca208c6550b2`.
The seven previous empty-file cases, eight native block-codec recipes and five
metadata cases continue to pass. No frozen fixture hashes or oracle sources
changed. Native GDX is pinned at
`9e2a8c8932412010cd7d2f94727d1740143bf3da`, zlib at
`da607da739fa6047df13e66a2af6b8bec7c2a498`; their identities are retained in JSON.
Native GDX interoperability here ran on Linux x86_64 under a 256 MiB address-space
cap, two CPU seconds and five wall seconds per invocation. This isolates the
oracle and is not a memory-cap qualification of the Rust writer.

## Resource scope and remaining work

Symbol controls reserve 16 KiB from the shared root, including fixed arrays of
20 keys/bounds/domain descriptors. The codec retains its existing audited fixed
allocation policy; its private infallible boxes are not newly described as
fallible. Membership frames, completion frames and metadata share the existing
scratch quota/handle; set membership uses O(log n) journal probes. Incremental
metadata/reference/completion scans can still be quadratic. The new recipe uses
a one MiB root in both codec modes. Library accounting is not an RSS measurement.

Writer RSS, OS-capped larger-than-RAM pipelines and throughput comparisons were
not measured in this task; task 023 owns those gates. Task 022 remains pending for
complete metadata/finalization qualification and the broader interoperability
inventory. Unsorted/string input, append, nonseekable output, duplicate recovery
and full modern API parity remain future work. No M3 release or performance
parity is claimed. The next eligible task is 022 once this gate is complete.
