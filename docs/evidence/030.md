## Deliverables and correctness

Writer::open_append returns a pending transaction owner; begin_append explicitly
imports into disk-backed metadata and the temporary output. All reader/encoder,
writer, journal and bounded-batch allocations share one root. Aggregate admission
covers the maximum output plus the whole metadata/sort scratch quota and two base
handles plus the configured scratch handle cap. There is no backup or second output.
Initialization/import failures retain ownership for abort retry.

Original UEL/symbol IDs, exact labels/text slots (including duplicates), acronym
IDs/order, alias chains/direct domain references, strict plus display metadata,
comments/descriptions/subtypes, physical empty scalars, error counts, set-text
flags and full audit/producer strings survive checked import. All prior records
are decoded and re-encoded; inherited strict membership is checked after all
prior set memberships exist, allowing forward catalog references. Existing metadata
and records cannot be overwritten. All four general-input adapters work for new
symbols. New metadata follows ordinary registration/freeze rules.

CreateNew publishes to an absent destination with no-clobber hard_link; both early
and late collisions fail without replacing another file. ReplaceSource requires
the canonical source pathname and explicit exclusive caller ownership. The library
checks source immutability during reads/import and before publication, checks the
pathname independently, syncs/closes the output, closes its source handle and uses
same-directory rename. Pre-publication failure/cancellation leaves the original
untouched by this library. External source edits are retained, not overwritten by
a failed transaction. Published cleanup failure remains published and reports the
error; abort retries owned scratch cleanup without deleting or rolling back output.

## Resource and performance limits

Fixed append author cases use a 4 MiB library root, a 4 MiB output cap, an 8 MiB
metadata/sort cap and ten admitted total handles. Peak charged root is 1136457
bytes, scratch 1306 bytes and per-job scratch handle peak one. Frozen rewrites
peak at 677598 charged root bytes and 1431127 scratch bytes, with per-job handle
peak one. Two additional admitted base handles cover source/output; the ten-handle
aggregate admission includes all configured scratch slots even when not used.
These are charged-root/admission metrics, not measured RSS or process-wide FDs.

The implementation always rewrites records to canonical little-endian v7 using
an explicitly selected raw/zlib output codec. It requires at least O(file-size)
record I/O plus strict-record rereads and O(output-size) new output space. Metadata
scans/lookups may be quadratic or worse. There is no raw-block reuse, claimed
throughput parity or OS/RSS/out-of-core append proof. Task 031 retains those gates.

Source integrity follows the Reader immutable-source length/mtime contract. It is
not a lock, cryptographic proof or competing-writer compare-and-swap. ReplaceSource
requires exclusive caller ownership through finish/abort. Same-size/restored-time
edits and indistinguishable inode swaps are outside the contract. No directory
fsync/power-loss recovery, filesystem ACL/ownership copying, portable fallible-close
API, in-place fallback or post-publication rollback is claimed. Names/labels and
subtypes outside the writer contract or nonempty set-text slot zero reject before
publication rather than coercing/remapping data.
