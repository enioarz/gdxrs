## Phase measurements

Small uses 1M/4M raw records, native-zlib records and 63-byte dictionaries, plus
131,072/524,288 one-record sidecars. Each case has three cold serial/build/open/
first-query trials and nine warm leading queries. Full-output, non-leading,
miss/skew, head/zero and late-position matrices retain original IDs/order/value bits.
Metadata universe queries synthesize IDs/zeros; complete dictionaries are separately
streamed and verified once per case, not a three-trial label benchmark.

## Resource scope and findings

All Rust workers self-check hard/soft 512 MiB Linux RLIMIT_AS under one 256 MiB root.
Index workers admit 12 GiB disk, two handles and a 1024-byte cache; the timer worker
has one source handle. Observed descriptors include stdio. Root peaks are at most
1,272,943 bytes and wait4 RSS at most 14,819,328 bytes, conservatively including
process-launch overhead. Native eager metadata uses
the separately declared 16 GiB reference cap (observed peak 385,949,696 bytes).

Largest raw/zlib/dictionary sources are 504,250,510 / 42,302,074 / 256,000,239 bytes.
The dense sidecar is 572,663,808 bytes from a 66,126,286-byte source. These growing
diagnostics do not establish new independent >4×-cap acceptance; 035 retains that
proof. Source/input/index/binary hashes, compiler, host/storage and CPU/RSS/I/O are
recorded. Sources are rehashed unchanged and results checked before owned sidecars
retire; source retirement follows all trials. Short workers may evade /proc samples;
self-checked limits and wait4 remain mandatory. Linux results are not macOS/Windows
memory or timing measurements.

- The validating sink takes roughly one fifth of record-scan time. Batch production
  is the first area for finer I/O/codec/assembly profiling, not proof of a specific
  optimization or parallel gain.
- Strict identity validation can dominate cold use. Future workers must share one
  validated coordinator session; per-worker reopen would repeat substantial work.
  Source hashing and canonical replay remain mandatory.
- Self-review found that per-case validation alone did not reject an omitted family.
  Added a whole-matrix guard and negative tests. An earlier owned baseline at
  `d0fb552` was interrupted to add this guard; its report/artifacts are retained and
  do not qualify completion. Final smoke/small use `1355585`.
- Contract self-review clarified EOF handling: a consumed nonempty range retains
  framing validation, while empty `[total,total)` and zero accepted-limit ranges
  remain lazy. Task 037 must test these separately.
- Task 037 follows review: prove exact serial half-open ordinal ranges before task
  038 adds workers. Decision 0031 requires shared stack/queue/reorder admission,
  global accepted limits, ordered backpressure and explicit cancellation/join errors.

No runtime threads, sampled CPU stacks, alternate codec, writer throughput change,
automatic planner, general speedup, independent approval or M6 release is claimed.
