## Implemented scope

`Writer::begin_string_records` borrows the writer before registration freezes.
Register symbol metadata first; existing UELs are supported. `begin_symbol(id)`
starts a contiguous input group; `write(labels, values)` spools arbitrary-order
rows without retaining caller slices. Phase finish builds the dictionary/remap
and replays each group through task 024. Explicit writer finish publishes.
Existing IDs precede new exact-byte labels in first-encounter order across groups.
No full dictionary, input-sized token array or record-offset table is retained.

One checksummed metadata-owned spool contains bounded frames for groups, values,
labels and appended ordinal mappings. It uses the existing journal quota half;
the mapping tail is admitted before bulk dictionary work. Sort runs retain the
other half. The same root admits the Store buffer, fixed controls, 20-token replay
keys and a fixed 1024-ID / 4 KiB mapping batch. Batching avoids per-key cache
switches between distant original/mapping offsets. Seven configured scratch
handles are required, with the extra spool slot deducted from the existing merge
allowance. No caller cap is raised. Conservative peaks include admitted mapping
space, rather than only bytes already written.

The parent closes the shared spool before failure cleanup, including while the
borrowing job still owns its control. Failed removal retains owned paths for
abort retry. Explicit raw-writer rejection preserves primary decoding errors;
dictionary cursor close and unconsumed-sorter cancellation preserve secondary
cleanup errors. Invalid/duplicate/domain/value failures and abandonment block
publication. Domain sets must finish before their dependent symbol groups.

## Independent semantic validation

The pinned native string author folds case through its hash table and encodes
negative zero as vm_zero. The first exploratory recipe rejected the assumption
that both authors would create identical streams. Pinned source inspection and
the complete dumps establish those differences. Task 025's explicit exact-byte
case policy and existing core bit policy remain unchanged: Rust retains A/a as
distinct labels and preserves -0. Native reads of Rust output preserve them too.
Each author has its own independent expected stream for these documented source
behaviors. No existing golden stream, frozen hash or assertion was weakened.

Five fixed cases cover raw default/minimal/all and zlib default/all, with strict
alias domains, repeated/case-distinct/non-UTF-8 labels, preexisting IDs, set/parameter,
20-dimensional variable, scalar equation, empty scalar defaults, special values,
acronyms and negative zero. Two generated cases add 8192 distinct 63-byte labels
in raw and zlib modes. Every UEL ID/byte, metadata item and ordered record is
compared in native-write/Rust-read and Rust-write/native-read directions, plus
Rust's own readback, against explicit recipes. Counts alone are not acceptance.

## Remaining limits

The public fresh-only bulk API remains unchanged; internal extension is used only
for the string phase. Label occurrences plus existing UELs are limited to
i32::MAX by its ordinal format. Groups are contiguous and each symbol occurs
once. Registration is frozen at replay; some domain/value/duplicate errors are
therefore discovered at phase finish. No error recovery or last-wins policy.
Fixed shared control allocations use infallible std constructors after budget
admission; no allocator-OOM recovery guarantee. Publication/durability limits
remain those of M3. No dependency, unsafe code, spill format, fixture hash or
quota increase. Task 026 (mapped registration/read/write) is next; 026–031 remain
pending and M4 is not release-qualified.
