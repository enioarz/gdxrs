## Delivered contract

`ScanCursor::checkpoint()` exports a fixed-size, root-charged `RecordCheckpoint`
from an unselected raw cursor. `row_ordinal()` identifies the next public raw row.
`Reader::scan_from_checkpoint` restores the same immutable open source/requested
symbol with fresh projections, batch cap, accepted limit and work counters. Reader
clones work; reopening identical bytes or substituting a resolved set for its alias
does not bypass source/symbol binding. Selected export is explicitly unsupported.

State includes codec/byte order/schema/count identity, bounds/widths, full preceding
20-key tuple, physical/block and decoded offsets, logical bytes and original ordinal,
including synthetic scalar/universe/EOF distinctions. Restore revalidates the bounded
data preamble and complete compressed restart block before skipping decoded bytes.
A pending terminator is still checked; consumed defaults never reappear. Export
root-budget denial is retryable, including failure after the point's own reservation
succeeds. Source/I/O/decode failures remain sticky with original diagnostics and no
partial point/batch. Cursor inline state and each retained point are root charged.

## Self-review findings and limits

A test-only fault control was initially read only with compression enabled, causing
minimal Clippy to fail. Added raw-path terminal I/O coverage instead of suppressing
warnings. Review also caught decoder initialization budget denial after successful
checkpoint reservation; export now remains retryable without consuming rows. The
fix required an explicit Result error type; the compilation failure was corrected
before rerunning all local gates and native qualification at the measured revision.

Structural state checks do not authenticate attacker-authored previous tuples or
summaries. This API is opaque and has no serialized import. Task 033 must establish
source content identity, sidecar trust/validation, versioning, paging, quotas and
atomic publication before accepting persisted checkpoints. Existing immutable-source
length/mtime checks are not cryptographic identity or a competing-writer lock.

Restore may reread the first data block for its preamble and the target block,
plus blocks needed by requested rows. Counters retain that work; no preceding records
are decoded. No persistent sidecar, automatic index build, indexed selection, parallel
scan, large-index resource qualification or acceleration claim is included. Production
dependencies and v7 GDX bytes are unchanged; M4 throughput limitations still apply.
